Use this template as the starting point for technical documentation. It includes a small set of components for common developer workflows without adding a large design system.

<Callout type="idea" title="Start with the reader's first task">
  The best first page answers three questions: what the product does, how to try it, and where to go next.
</Callout>

## What to document first

<Steps>
  <Step>
    ### Installation

    Show the shortest working setup path. Include package manager tabs when teams use different tooling.
  </Step>
  <Step>
    ### First successful call

    Provide one complete example that users can run without reading the full API reference.
  </Step>
  <Step>
    ### Core concepts

    Explain the vocabulary users need before they can make good decisions.
  </Step>
  <Step>
    ### Production concerns

    Cover authentication, limits, retries, observability, and deployment notes.
  </Step>
</Steps>
